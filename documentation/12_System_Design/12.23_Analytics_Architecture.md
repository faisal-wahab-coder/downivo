# 12.23 Analytics Architecture

**V1 replica:** `packages/analytics` is a Melos member. Events no-op until Firebase `google-services.json` and PostHog `POSTHOG_API_KEY` are configured. Full spec: [31_Observability_Analytics.md](../31_Observability_Analytics.md).

## Shape

```
Flutter app (app_core + download_engine)
        │
        ▼
 AnalyticsService   ← only public API for events / breadcrumbs
        │
        ├── Crashlytics adapter   crashes, ANRs, non-fatals, custom keys
        ├── PostHog adapter       product events, funnels, sessions
        └── AppLogger             structured local/diagnostic logs
```

One vendor per purpose. UI and engine must not import Firebase or PostHog SDKs directly.

## Privacy

Never send full URLs, query strings, tokens, cookies, file contents, or private social/Telegram URLs. Track `platform`, `media_type`, `resolution`, `error_category`, `downloadId`. Map `SocialPlatform.twitter` → analytics `x`. See 31 §3 and §4.

## First slice (Phases 1–5)

Crashlytics + `AppLogger` + `AnalyticsService` events for lifecycle, URL paste, platform detect, resolve, download start/complete/fail, funnel. Then 2–4 weeks of production data before new product features.
