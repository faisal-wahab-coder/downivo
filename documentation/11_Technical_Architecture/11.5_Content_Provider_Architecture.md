# 11.5 Content Provider Architecture

`ContentProviderRegistry` selects a resolver by URL. Each platform file implements discover/canHandle.

Supporting types: `SocialPlatform` enum, `DiscoveredResource`, `social_url_utils.dart`, `social_http_headers.dart`, `media_extractor.dart`, `platform_social_resolver.dart`.

## Resolver files (required)

- youtube_resolver.dart
- tiktok_resolver.dart
- instagram_graphql_resolver.dart
- facebook_resolver.dart
- twitter_resolver.dart
- reddit_resolver.dart
- pinterest_resolver.dart
- linkedin_resolver.dart
- threads_resolver.dart
- soundcloud_resolver.dart
- vimeo_resolver.dart
- twitch_resolver.dart
- telegram_resolver.dart
- snapchat_resolver.dart
- whatsapp_resolver.dart
- dailymotion_resolver.dart (+ dailymotion_uri.dart)

Host matching lives on `SocialPlatform` (youtu.be, pin.it, t.me, wa.me, tg://, snapchat://, etc.).

If no resolver handles the URL, treat as **generic HTTP download**.

Auth-walled / private CDN URLs must fail with a clear error, not hang.

Extensive per-platform tests exist under `download_engine/test` — recreate equivalent coverage (URL classification, metadata, security negatives).
